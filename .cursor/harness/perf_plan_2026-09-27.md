### Two conclusions from the fresh data are wrong

1. **The CR component filters are not a hotspot.** `detect_cosmic_rays` is
   26.6s *tottime*, i.e. astroscrappy's C code, and `_post_filter_components` /
   `_filter_faint_components` / `regionprops` do not appear in the top 35 at all.
   The 0.67ms-per-component axis-length cost measured in
   `cr_filter_options.md` is real but there are nowhere near enough components
   for it to matter. Options A-E there are not worth doing. The only CR lever is
   the science knobs (`sigclip`, `niter`, `min_component_area`).
2. **`background.py` is done.** `estimate_background` is 3.8s / 1% across four
   calls. The spline work and the prior round's changes landed; there is nothing
   meaningful left there.

### What is actually left in scope

- `bad.py`: 71.4s, but it is a **cold-cache** cost -- `compute_flat_bad_mask` is
  tiled over the flat and cached per (flat, settings); the Sep-9 stage table
  shows `bad_flat` at 0.009s/HDU once warm. So this is first-run latency, not
  steady-state throughput. It has the same shape as the streak hotspot though:
  `_detect_bad_pixels_local` runs `median_filter(size=15)` per 1024^2 tile,
  ~4.7s/tile, 15 tiles.
- `cosmics`: only the science knobs.
- Everything else is under 2%.

**Net: with `streaks.py` excluded, this round has very little headroom left.**
The remaining in-scope work is a cold-start optimization plus a science-knob
curve. The dominant cost, and the single hottest line in the package, are both
inside `streaks.py`.

## Phase 2 — Confirmed structural win: the size-15 median filter

`streaks._streak_image_core` (streaks.py:117): `ndi.median_filter(positive, size=15)`.
- Measured now: 7.6 s for 1024^2, scaling as O(N*k^2) (4.2x cheaper at size=7).
  The stale profile put this at 12.7 s/CCD/call, 2 calls, ~42% of a CCD.
- The output feeds `prepared = clip(positive - filtered, 0)`. Most of a CCD is sky,
  where the result is provably 0 under both a cheap and the exact filter. So:
  cheap filter everywhere + exact size-15 only near the decision cut.
- This is the idiom already proven in this file (`_prune_small_edges` +
  `_PERIMETER_ORDER_EPS`): fast vectorized path, exact re-measure near the cut.
- Must be **bit-identical**. Gate on `pixi run science-gate` + the MegaCam
  product comparison, not just the unit suite.

## Phase 3 — CR component loop (measure first, then decide)

`cosmics._filter_faint_components` -> `_axis_lengths`.
- Measured now: `axis_major/minor_length` costs ~0.67-0.75 ms **per component**
  (3.2k components -> 2.45 s). If the real count is tens of thousands this
  dominates the CR stage, which was 14% of a CCD.
- If confirmed, the fix is exact: per-label inertia-tensor eigenvalues via
  `bincount` over coords, i.e. the same formula skimage uses, evaluated for all
  labels at once. Hoist the `area` gate first if it is not already effective.

## Phase 4 — Debuggability decisions (need input, not more measurement)

- `print()` -> `logging`: still open (previously deferred as D8). Every silent
  path now prints an ad-hoc warning, so a real logger with per-HDU context would
  help. It is a behavior change; needs a decision, not a patch.
- Bench logs are 2-3 MB of prints per run. A `--quiet`/log-level would make
  benchmark output readable and diffable.

## Checked and rejected (do not redo)

- **Phase 3 (CR component loop) is dead — do not implement.** The fresh profile shows
  `detect_cosmic_rays` is 26.6s *tottime* (astroscrappy's C) and neither
  `_post_filter_components` nor `_filter_faint_components` nor `regionprops` appears in
  the top 35 at all. The 0.67 ms/component axis-length cost is real but there are nowhere
  near enough components to matter. The full option space, including a *validated*
  closed-form eigenvalue vectorization (5.65e-11 max rel error, 1-in-1940 decision flip,
  fixable with an epsilon band), is in `cr_filter_options.md` — kept because it becomes
  relevant if the CR stage ever grows, not because it should be done now.
- `distance_transform_edt(..., return_distances=False)` in `_repair_negative_dips`:
  measured **2.2x slower** (283 ms -> 633 ms), not faster. Dropped.
- `astype(copy=False)` / removed `np.array(copy=True)` in mef: verified safe;
  `fitsio.read()` returns an owning writable array for plain and RICE_1 images.
- The iteration-0 background reuse and the float32 dip-repair downcast: reverted
  in `9f481f7`, both were behavior changes with no upside.
- A faster *exact* 15x15 median for `bad.py`: there isn't a drop-in one.
  `skimage.filters.rank.median` cannot even run on ADU-scale flats — it requires `uint8`
  or float in [-1, 1] and raises `ValueError: Images of type float must be between -1
  and 1`. And `bad_flat` is 0.009 s/HDU once the per-flat disk cache is warm, so the
  71 s cold cost is first-run latency, not steady-state throughput.
- `np.histogram(bins=100, range=(lo,hi))` as a drop-in for the array-edge form: **not
  equivalent** (different bin edges, and out-of-range values are dropped rather than
  clipped), even though it is 14x faster. The committed fix pre-filters instead.

## Next round: open `streaks.py`

65 % of per-CCD wall time, and the single hottest line in the package is
`skimage.transform.warp` inside `_radon_projections` at 117.4 s (36 % of the whole
package). `median_filter` is 86.6 s over 12 calls. `bucket_key` + `builtins.round`
together are 9.3 s of pure Python call overhead across 1,431,238 `round` calls —
that last one is a cheap, safe, local win.

Phase 2 above (the size-15 median, cheap filter + exact re-measure near the cut) is
the biggest single opportunity and is still unstarted.

Two measurement lessons worth keeping:
- cProfile's top-N cut made a ~1.3 s/amp stage look *absent* rather than cheap. Trust
  the `_timed` stage instrumentation for anything under a few percent, and consider
  wiring the stage table into the profile output so the blind spot closes.
- Every optimisation here was checked by measuring, and twice the measurement
  contradicted the prediction (the EDT flag above; the first closed-form eigenvalue
  attempt, which was simply transposed). Cheap benchmarks beat confident reasoning.
